# Music Retrieval from EEG Using Contrastive Learning 

Code accompanying the ICASSP 2027 submission on retrieving aligned music from EEG recorded during naturalistic listening.

The main model learns a shared temporal embedding space for five-second EEG windows and frozen MERT audio features. The repository also contains the reported ridge-regression, cosine-regression, and EEG2Mel baselines, deterministic split generation for all five evaluation regimes, and Table I result formatters.

## Repository layout

  table1_infonce_subject_off.yaml Explicit Table I subject-layer-off condition

  create_window_metadata.py      Build aligned five-second EEG/MERT metadata
  create_splits.py               Generate deterministic five-fold split CSVs
  run_contrastive_25fold_pipeline.sh Reproduce all base contrastive runs
  run_ridge_25fold_pipeline.sh   Reproduce all ridge-regression runs
  run_eeg2mel_25fold_pipeline.sh Reproduce all reported EEG2Mel runs

Research-only audits, exploratory plots, and duplicated segmentation workspaces
are intentionally excluded from this branch.

## Installation

Python 3.13 is the development environment used for this branch.

```bash
python -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
```

The Python code, configs, and local launchers resolve runtime paths from the
repository root, so the checkout may be placed anywhere. Commands in this
README assume the repository root is the current directory. Local launchers
accept `--venv` when the environment is not at `.venv`.

The NMED-T recordings and audio are not distributed in this repository. Place
the full-song WAV files at `data/songs/song21.wav` through
`data/songs/song30.wav`; generated metadata, tensors, checkpoints, and logs are
kept out of version control.

## Required preprocessed EEG files

The preprocessed NMED-T EEG recordings are source data and are not generated by
this repository. Place them under the repository root as follows:

```text
<repository>/data/processed/
  song21_Imputed.mat
  song22_Imputed.mat
  song23_Imputed.mat
  song24_Imputed.mat
  song25_Imputed.mat
  song26_Imputed.mat
  song27_Imputed.mat
  song28_Imputed.mat
  song29_Imputed.mat
  song30_Imputed.mat
```

Each song file must contain the matching MATLAB variable (`data21` through
`data30`) and the sampling-frequency value `fs`, as expected by
`scripts/load_data.py`.

These files must be in place before running the data-preparation command below,
because `scripts/create_window_metadata.py` reads them to create the windowed
EEG tensors and metadata used by the downstream split, training, and evaluation
pipelines. They are not required merely to install the environment, view command
help, or run tests that provide synthetic or mocked data. For a clean
end-to-end reproduction, stage both these files and the full-song WAV files
before beginning data preparation.

## Paper configurations

Each split-specific file extends `configs/base.yaml`, so shared model settings are defined once while the split and run name remain explicit.

| Evaluation regime | Config | Generated folds |
| --- | --- | --- |
| Chunk out | `configs/chunk_out.yaml` | `chunk_out_fold0.csv`–`fold4.csv` |
| Random segment out | `configs/random_segment_out.yaml` | `random_segment_out_fold0.csv`–`fold4.csv` |
| Song out | `configs/song_out.yaml` | `song_out_fold0.csv`–`fold4.csv` |
| Subject out | `configs/subject_out.yaml` | `subject_out_fold0.csv`–`fold4.csv` |
| Subject + song out | `configs/subject_song_out.yaml` | `subject_song_out_fold0.csv`–`fold4.csv` |

The checked-in configs select fold 0 for training and evaluation. To run another fold, change both `training.filename` and `testing.filename` to the matching generated fold; all other paper settings remain inherited from `base.yaml`.

## Data preparation

Create new five-second EEG windows in microvolts and MERT features:

```bash
python -m scripts.create_window_metadata \
  --window-length 5 \
  --output data/metadata/five_sec_windows.csv
```

MNE still receives volts from the existing loader. After epoching, EEG is
multiplied by the fixed factor `1e6`; no input centering or scale parameters are
estimated. EEG is saved under `data/eeg/uv/5s/`, with `eeg_unit: uV` in each
tensor and metadata row. The generator also recreates MERT features under
`data/audio/mert/5s/`. It does not convert the old robust-scaled tensor cache.

Generate fresh splits for the contrastive and cosine-regression runs:

```bash
python -m scripts.create_splits --config configs/all_splits.yaml
```

These 25 folds use the original seeds and fractions and are written to
`runs/icassp2027-uv-splits/splits/`. The EEG2Mel launcher separately prepares
the required `mel_path` metadata and matching split files. The executable
configuration uses 60% training, 10% validation, and 30% test data; the emitted
split CSVs are the authoritative assignments for every model condition.

All training examples below use UV inputs. The main model, cosine ablation, and
ridge baseline share `runs/icassp2027-uv-splits/splits/`. EEG2Mel prepares
matching folds under `runs/eeg2mel_uv/splits/` with the additional `mel_path`
column. Archived robust-scaled runs retain their original saved configurations.

## Reproducing Table I

Table I is a four-method by five-split by five-fold experiment, for 100 trained
models in total:

| Table column | Objective | Subject layer |
| --- | --- | --- |
| Subject Layer On | Symmetric InfoNCE | Enabled |
| Subject Layer Off | Symmetric InfoNCE | Disabled |
| Cosine Regression | Paired `1 - cosine` | Enabled |
| EEG2Mel | Mel-spectrogram MSE | Not applicable |

Complete the [data preparation](#data-preparation) steps first. Then run the
three direct EEG-to-MERT conditions with the contrastive 25-fold launcher:

```bash
scripts/run_contrastive_25fold_pipeline.sh \
  --config configs/table1_infonce_subject_on.yaml \
  --venv .venv

scripts/run_contrastive_25fold_pipeline.sh \
  --config configs/table1_infonce_subject_off.yaml \
  --venv .venv

scripts/run_contrastive_25fold_pipeline.sh \
  --config configs/table1_cosine_regression.yaml \
  --venv .venv
```

Run the EEG2Mel condition with its 25-fold launcher:

```bash
scripts/run_eeg2mel_25fold_pipeline.sh \
  --config configs/eeg2mel_paper.yaml \
  --output-prefix table1-eeg2mel \
  --venv .venv
```

Each invocation trains and evaluates five folds for all five evaluation
regimes, for 25 models per method and 100 models in total. The EEG2Mel launcher
also creates its mel targets and matching split files. Both launchers call
`scripts.average_test_results` after evaluation to write one aggregate CSV per
evaluation regime under the method's `average_metrics/` directory.

Use `--dry-run` with either launcher to inspect its commands without training.
Resume an interrupted method with the same command plus `--skip-completed`.
For EEG2Mel, add `--skip-mel-targets` and/or `--skip-splits` when those inputs
already exist.

The completed method outputs are:

```text
runs/final_results/table1-infonce-subject-on/
runs/final_results/table1-infonce-subject-off/
runs/final_results/table1-cosine-regression/
runs/final_results/table1-eeg2mel/
```

The launchers normally perform averaging automatically. To rebuild the five
aggregate CSVs for a completed method without training or evaluation, run
`scripts.average_test_results` directly; for example:

```bash
python -m scripts.average_test_results \
  runs/final_results/table1-infonce-subject-on \
  --output-dir runs/final_results/table1-infonce-subject-on/average_metrics \
  --output-prefix table1-infonce-subject-on
```

To inspect one method's averaged results as a Table-I-style table, use:

```bash
python -m scripts.format_average_metrics_table \
  table1-infonce-subject-on \
  --format markdown
```

To combine existing per-run `results_table.tex` files into one wide
`runs/final_results/final_table.tex`, pass the run names in the desired column
order:

```bash
python -m scripts.format_average_metrics_table \
  --concatenate-runs \
  table1-infonce-subject-on \
  table1-infonce-subject-off \
  table1-cosine-regression \
  --standalone
```

The `--standalone` option adds a complete LaTeX document wrapper and loads the
`booktabs` package used by the tables. This makes `final_table.tex` directly
compilable instead of requiring a separate wrapper file. It can also be used
with one run when `--format latex` is selected.

The combined table follows the manuscript's two-panel layout: every supplied
run becomes an `R@1`/`κ` column group, marginalized song identification appears
in panel (a), and within-song retrieval appears in panel (b). The largest κ is
bolded across the supplied runs for each data split and panel.

To preview the generated table in PyCharm:

1. Install a LaTeX distribution such as MacTeX or TeX Live.
2. Install the
   [TeXiFy-IDEA](https://plugins.jetbrains.com/plugin/9473-texify-idea) and
   [PDF Viewer](https://plugins.jetbrains.com/plugin/14494-pdf-viewer) plugins
   from **Settings | Plugins | Marketplace**, then restart PyCharm.
3. Open `runs/final_results/final_table.tex` and use the TeXiFy run action or
   gutter icon to compile it. The resulting PDF opens in PyCharm's PDF viewer.

After all four method runs exist, build the combined paper table with:

```bash
python -m scripts.format_table1 \
  --format latex \
  --output runs/final_results/table1.tex
```

The formatter reads `song_identification_marginal_top1` and
`within_song_r_at_1` from every split-family aggregate. It preserves the Table I
row order and bolds the method with the largest unrounded mean kappa in every
row and panel.

## Contrastive model

Run one split-specific experiment with:

```bash
python -m scripts.train --config configs/chunk_out.yaml
python -m scripts.test --config configs/chunk_out.yaml
```

Run all 25 folds from a generated split run with:

```bash
scripts/run_contrastive_25fold_pipeline.sh \
  --venv .venv
```

The launcher trains every fold first, then evaluates the best available
checkpoint for each fold. Use `--skip-completed` to resume a partial sweep.
It defaults to `configs/infonce_paper.yaml` and uses that config's `run_name`,
`icassp2027-uv-infonce-25split`, as the output prefix.

Training writes checkpoints under `runs/checkpoints/<run_name>/`. Evaluation writes retrieval, song-identification, localization, and permutation summaries under `runs/<run_name>/`.

### Same-encoder cosine-regression ablation

`configs/cosine_regression_paper.yaml` changes only the scientific setting under
test: it replaces InfoNCE with `1 - cosine` between each EEG output and its
paired MERT target, computed jointly over the complete feature-by-time
representation. It also supplies a distinct output name. The encoder, direct
768-dimensional alignment, subject-layer setting, splits, training seed,
optimizer, and retrieval evaluation remain inherited from
`configs/infonce_paper.yaml`.

Run the complete matched 25-fold ablation with:

```bash
scripts/run_contrastive_25fold_pipeline.sh \
  --config configs/cosine_regression_paper.yaml \
  --venv .venv
```

New checkpoints record the objective name and state explicitly. Evaluation also
continues to load legacy InfoNCE checkpoints that contain only
`clip_state_dict`.

## Ridge baseline

The ridge baseline standardizes flattened five-second EEG windows, learns a
regularized linear mapping to mean-pooled MERT targets, and evaluates the
predictions with the same retrieval and song-search benchmark as the main
model. Its output includes both max-window song identification and the
length-normalized marginalized song-identification metric, with permutation
null statistics and upper- and lower-tail p-values.

Run all five folds of all five split families with:

```bash
scripts/run_ridge_25fold_pipeline.sh --venv .venv
```

The launcher reads `configs/ridge_paper.yaml`, uses the shared UV splits, and
writes the 25 fold runs plus five averaged metrics files under
`runs/final_results/ridge-uv-25split/`. Use `--skip-completed` to resume a
partial sweep or `--dry-run` to inspect the command. Ridge strength,
permutation counts, and the marginalized song-search temperature can be
overridden from the launcher; run it with `--help` for the complete list.

## EEG2Mel baseline

The paper reports the five-second EEG2Mel baseline preserved from the
`feature/eeg2melembed` experiment branch. It divides every five-second EEG/audio
row into five one-second training targets, reconstructs a five-second waveform,
embeds that waveform with frozen MERT, and applies the same retrieval benchmark
as the contrastive model.

Run the complete 25-fold EEG2Mel workflow locally with:

```bash
scripts/run_eeg2mel_25fold_pipeline.sh
```

The launcher discovers the repository and active Python environment. Use
`--venv` when needed, or `--dry-run` to inspect every command without
preprocessing or training. The standalone settings in
`configs/eeg2mel_paper.yaml` use UV metadata, mel targets under
`data/mel_targets/uv/5s/`, and splits under `runs/eeg2mel_uv/splits/`. Training
and evaluation use the output prefix `eeg2mel-uv-25split`.

## Reproducibility status

The end-to-end Table I workflow is a procedural reproduction using the current
fixed-microvolt inputs and pinned environment. The paper and repo use Python 3.13 and
PyTorch 2.13. The original training implementation did not explicitly seed model
initialization. Fresh training reproduces the experiment rather than guaranteeing identical
floating-point results.
